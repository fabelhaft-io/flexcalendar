### Findings that do not block (follow-ups, in `docs/reviews/follow-ups/from-E05-R10.md`)

1. **P5.** The generic error handler copies nothing from an exception today, but no test sends a hostile exception through it, so a later edit that copies `error.message` into a body would pass. The first route test of E05-R03 or E05-R04 that throws a marker kills it.
2. **P9.** The `PROPERTY_NAME` check in `classifyCalDavError` duplicates the adapter's filter and nothing tests a name that fails it.
3. **Q3.** Nothing pins that `dav_failure` is logged for 500 and above only.
4. The problem `type` URIs (`https://flexcalendar.de/problems/<slug>`) are not served by anything; RFC 9457 says a `type` URI should resolve. Decide with E08 before a client switches on them.
5. `405` is in the table and the spec, but Fastify answers `404` for a known path with another method, so it is never sent.

## Brief (condensed)

One problem+json model for every API error (`server/api/src/problem.mjs`), a correlation ID that is generated and never trusted, one fixed-field log line per request, the matching CalDAV access and delegation lines, a `400` for a malformed `REPORT` body, the contract test comparing content types and real responses, and the marker scan over both services' logs (`make check-log-canaries`).
