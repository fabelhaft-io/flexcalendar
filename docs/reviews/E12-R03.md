### Findings, none a fix request here

1. **A frozen vector cannot hold, and the implementer was right.** `aad-v1.json`'s `aad-calendar-id-uppercase-refused` is built as `CALENDAR_ID.upper()`, and `CALENDAR_ID` is `11111111-1111-4111-8111-111111111111`: all digits, so the input equals the positive `aad-event-master` while the vector expects `E_ENCODING`. The library accepts those (canonical) inputs; `test/aad_vectors_test.dart` names that one vector, asserts it duplicates the positive one, and adds the check it meant to pin (`AAAAAAAA-AAAA-4AAA-8AAA-AAAAAAAAAAAA` → `E_ENCODING`). Also from the run: `generate.py`'s `canonical_recurrence_id` would raise `E_UNSUPPORTED` for a floating `RECURRENCE-ID` where the vector and §5.2 say `E_SKELETON` (the vector is right; the generator's path is unreached), and neither `build_aad` nor `canonical_recurrence_id` is among the generator's self-check runs. The vectors are E12-R01's, frozen and owner-approved, so the fix waits for the owner (follow-ups).
2. **`pubspec.lock` is not committed**: the root `.gitignore` ignores `packages/*/pubspec.lock` by E02-R02's decision (a library does not pin its consumers). My brief said to commit it; the brief was wrong, the repository's rule stands.
3. **Two dependencies beyond `sodium`**, both pinned exactly: `timezone` 0.11.2 (ADR 0002 names it for every `TZID` calculation in Dart; §5.2's canonical `RECURRENCE-ID` needs an instant, and the library applies §3.4's answers on top of the package's offsets) and `crypto` 3.0.7 (dart.dev's own, for §5.1's SHA-256). The bundled tzdata is 2026e, Node's ICU 2026b; the AAD binds wall clock (§3.5), so envelopes don't depend on it, only the `recurrence_id` instants of a zone whose rules changed.
4. **Check order:** the ceiling is checked as soon as the payload bytes exist, before §4.3's value rules; §1.2 lists it last. Both orders give every vector's answer (encryption cannot change the length); worth one sentence in the spec when the vectors are next touched.
5. `openEvent`/`openCalendarMetadata` return the validated payload bytes, not a parsed map (E13-R02 and the app are the first callers).

### What to build

1. `packages/crypto_dart` as a Dart package (no Flutter dependency): `seal`/`open` for the **event** envelope and for the **calendar-metadata** envelope (D-18), with the AAD built inside the library from the calendar id, the skeleton values and the header's epoch (§1.3 step 4: never from a separate argument), the payload serialised and validated per §4 (JCS, the member rules), and the §0.3 error codes as a typed result or exception, in §1.3's check order. `seal` draws its nonce from libsodium's CSPRNG; a **test-only** entry point takes the nonce (§1.2 step 4), not exported from the public library file.
