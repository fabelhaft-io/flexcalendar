# Review — E12-R03 · Envelope seal/open

## Brief for run 1

The requirement is in `docs/epics/E12-crypto-core.md` § E12-R03. **Phase 2: the Dart library only** (`packages/crypto_dart`); the TS library is Phase 5. The spec is `spec/crypto.md` (accepted 2026-10-12) — §0 conventions and error codes, §1 the envelope, §2 the AADs, §3 the canonical timing fields, §4 the payload (JCS), §5.1 the envelope hash — and the vectors in `spec/crypto-vectors/`. Executor `agent+review`. Writable paths: `packages/crypto_dart/`.

### What to build

1. `packages/crypto_dart` as a Dart package (no Flutter dependency): `seal`/`open` for the **event** envelope and for the **calendar-metadata** envelope (D-18), with the AAD built inside the library from the calendar id, the skeleton values and the header's epoch (§1.3 step 4: never from a separate argument), the payload serialised and validated per §4 (JCS, the member rules), and the §0.3 error codes as a typed result or exception, in §1.3's check order. `seal` draws its nonce from libsodium's CSPRNG; a **test-only** entry point takes the nonce (§1.2 step 4), not exported from the public library file. Open never returns partial plaintext.
2. The canonical timing fields of §3 as the library computes them from parsed skeleton values (`DTSTART`, the end, `RRULE`), because the AAD depends on them; and §5.1's `X-CALFLEX-ENVELOPE-SHA256` check before opening.
3. **Tests that read the vector files themselves** from `../../spec/crypto-vectors/` (never a copy): every positive and negative vector of `envelope-v1.json`, `metadata-envelope-v1.json`, `aad-v1.json`, `canonical-timing-v1.json` and `payload-jcs-v1.json`, each asserted to its expected bytes or its exact error code. Report how many vectors each file contributed, and fail if a file contributes none (a test over an empty list proves nothing).

### Facts and constraints

- **Dependency:** `sodium` 4.1.1+2, directly (E12-R02: `sodium_libs` is discontinued and only re-exports it). It builds libsodium 1.0.22 through a build hook that `dart test` and `dart run` honour; `dart <file>.dart` does not. Pin exactly, commit `pubspec.lock`. Dart SDK `^3.13.5` stays (the pin in `packages/crypto_dart/pubspec.yaml`, from Flutter 3.47.6).
- **The gate:** `infra/scripts/verify.mjs` runs `dart pub get`, `dart format --set-exit-if-changed`, `dart analyze --fatal-infos` and `dart test` on the package once it has Dart sources (`make verify-packages-crypto_dart`). CI already installs Flutter (and so Dart) for this component (`.github/actions/setup/action.yml`).
- **HKDF and key material are E12-R04**, not this requirement: here the CCK is an input.
- **JCS:** write the serialiser to §4.1's rules and prove it on `payload-jcs-v1.json`; no unvetted JCS package.
- **INV-07:** nothing under `server/**`. **INV-12/D-17:** no function takes a password.
- **DST:** §3.4 pins RFC 5545's answers; the AAD binds `TZID` + wall clock (§3.5), so no zone database enters the AAD — don't add one.
