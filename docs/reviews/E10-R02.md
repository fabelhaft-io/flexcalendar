### Findings

1. **A relaunch drops the session.** `AuthController.build()` returns `SignedOut`, so after the app is closed the user signs in again although secure storage holds a refresh token (your `openQuestions` names it). Keeping tokens in `flutter_secure_storage` exists for exactly this; it belongs to Auth, not to the cache (E10-R03) or the time zones (E10-R04).
2. **Plain HTTP is allowed in every flavor.** `AppAuthOidcClient` sets `allowInsecureConnections` from the issuer's scheme, so a `staging` or `prod` build given an `http://` issuer through `CALFLEX_OIDC_ISSUER` would send the login over plaintext. iOS and the stack demand TLS (`docs/02`), and only a developer's `dev` build has a reason to differ.

### Fix requests

1. **Restore the session on start:** read the stored tokens; with a refresh token, refresh (or use a still-valid access token) and confirm with `GET /me`, then show the signed-in state; a failed refresh or a `401` from `/me` signs out through the same path as a manual sign-out (hooks included). Test: a relaunch with valid tokens is signed in without the browser; with an expired, refreshable token it refreshes once; with a rejected refresh token it signs out and runs the hooks.
2. **HTTPS only outside `dev`:** `allowInsecureConnections` may be true only for the `dev` flavor (and only for an `http://` issuer); `staging` and `prod` refuse a non-`https` issuer at start, loudly, as a missing client id does. Test both.

Change nothing else.

## Brief for run 1

The requirement is in `docs/epics/E10-mobile-app.md` § E10-R02; the spec is D-03 (Zitadel, OIDC + PKCE, JWT access tokens), ADR 0004, and E02-R09's configuration in `infra/zitadel/main.tf` (application `de.flexcalendar.app`, native, public client: `OIDC_AUTH_METHOD_TYPE_NONE`, code + refresh-token grants, redirect `de.flexcalendar.app:/oauth2redirect`, post-logout `de.flexcalendar.app:/logout`). Writable paths: `apps/mobile/`. Android only; iOS waits for Phase 5.

### What to build

1. **Sign-in** with `flutter_appauth` (Authorization Code + PKCE S256, always) against the flavor's issuer: `https://auth.localhost:8443` for `dev`, `https://auth.staging.flexcalendar.de` for `staging`, `https://auth.flexcalendar.de` for `prod` (`docs/02` § Hosting). The **client ID is generated by Zitadel** (`infra/zitadel/outputs.tf` → `android_client_id`), so it reaches the build as a `--dart-define` (say `CALFLEX_OIDC_CLIENT_ID`), never hard-coded; a build without it fails loudly at start, as `flavorProvider` does. Scopes: `openid profile email offline_access` plus the project audience scope `urn:zitadel:iam:org:project:id:<project_id>:aud` (the project id as another `--dart-define`) — from `docs/reviews/follow-ups/from-E05-R01.md`.
2. **Tokens** in `flutter_secure_storage` only (Android Keystore-backed); never in logs, never in shared preferences.
3. **A `dio` interceptor** on the one `dioProvider` (`lib/src/api/api_providers.dart`) that adds the bearer token, refreshes it when it has expired or is about to, retries the request once after a `401` with a refreshed token, and serialises concurrent refreshes (one refresh for N parallel requests). A failed refresh signs the user out.
4. **Sign-out**: end the session at Zitadel (the post-logout redirect), clear the tokens, and run a sign-out hook list that later requirements register into: the offline cache (E10-R03), the keys (E12-R06) and, in Phase 4, the push token (E07-R03). Those don't exist yet; the hook and a test that it runs are this requirement's part.
5. The Android manifest's redirect scheme `de.flexcalendar.app` (the `appAuthRedirectScheme` placeholder). All flavors keep the one application ID (E10-R01).
