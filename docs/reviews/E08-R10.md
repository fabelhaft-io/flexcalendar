## Review 1 (BLOCKED)

`bash option-c.sh` (and every other script) exits 1 at once: `./lib.sh: line 45: PROJECT: readonly variable`. Each option script declares `readonly PROJECT=…` (and `COMPOSE_FILE`, `HTTP_PORT`) and then sources `lib.sh`, which assigns `PROJECT=""`, `COMPOSE_FILE=""`, `HTTP_PORT=""`, `HEALTHY_SECONDS=""`. Patched in a scratch copy with `: "${NAME:=}"` for those four lines, the next run stopped at `lib.sh:118`: `printf: ->: invalid option` (`printf '-> %s …'`); patched with `printf -- '-> …'`. The scripts are also committed as mode `0644`, while the README and the scripts' headers say `./option-c.sh`. Nothing else was changed in the copy.

### Findings

- The harness does not run as committed (above): three bugs.
- **A password reaches the output.** `pg_sql` masks the command it echoes, but when `psql` fails, `podman compose exec` prints its own `Error: executing … -e PGPASSWORD=zre-throwaway-zitadel …` line unmasked (every expected-denial check in A and B2 does this). The brief said the harness prints no password, throwaway or not.
- Option B leaves its project running on failure, while the README and the script header say each script removes its own project at the end.
- The scripts' headers say "Measured on 2026-10-12: this starts …" although no container run had happened; the ADR's numbers come from `local-binary-probe.sh` (a local Zitadel binary and Postgres) and are labelled as such, which is fine, but the container rows were `pending`.

### Fix requests

1. Make the harness run as committed: `lib.sh` must not reassign a variable an option script made readonly; `printf --` (or a format that doesn't start with `-`); mode `0755` on the five scripts (`git update-index --chmod` is not yours, so say in `openQuestions` if the coordinator's commit cannot carry the mode, and keep `bash option-x.sh` in the README as the documented form).
2. No password in any output: pass `PGPASSWORD` without putting it on a command line `podman` echoes (an env file inside the throwaway project, a `.pgpass` in the container, or `podman compose exec … -e PGPASSWORD` replaced by an environment the service already has), and filter every `pg_sql`/`pg_meta` output through `mask` including stderr.
3. Option B: tear its project down on failure too (a `trap`), or say in the README and the header that it is left for inspection and how to remove it.
4. **Fill in the ADR from `results/2026-10-12/`**: § 1–6's `pending` cells, the measured table above (cite the log files), and the headers' "Measured on" lines (they now have a source). Keep the local-binary results where they add something the container runs don't (§ 5's `init` privilege matrix), labelled as the local probe. Keep the ADR `Proposed`.

Change nothing else.
