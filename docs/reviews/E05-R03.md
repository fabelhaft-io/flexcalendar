### Fix requests (one run)

1. **The spec does not generate.** `swagger_parser` 1.45.0, the pinned one, dies on the path-level `parameters:` of `/calendars/{id}` (`type 'List<Object?>' is not a subtype of type 'Map<String, dynamic>'`: it casts every path-item member to a map before it skips `parameters`), prints "No schemes were generated", and `make gen` still exits 0 with `apps/mobile/lib/api` empty. Remove the path-level list and declare the `id` path parameter on `patch` (first, before `If-Match`) and on `delete`; add a comment in the spec saying why. I applied exactly that and reverted it; `make gen` then worked.
2. **A non-UUID id is a 500, not the 404 an unknown id gets (E03-R01).** Postgres raises `22P02` for `calendar_id = 'not-a-uuid'`. Answer `404` for an id that is not a UUID, in `PATCH` and `DELETE`, before the store is asked. Make the fake store in `test/support/calendar-store.mjs` throw like Postgres does on a non-UUID, so the unit tests would have failed; add the cases to `calendars.test.mjs` and to the integration suite.
3. **Test isolation.** The refused-envelope test counts all of user `a`'s calendars, and the previous test already created one. Count before and after and assert no change.
4. **Kill M8.** Tests through `GET /calendars` and `POST /calendars` that a first-sight user with a verified e-mail gets their `users` row on the first call, and that an unverified e-mail is refused exactly as `GET /me` refuses it and creates no row. Show the mutant fails.
5. **README:** the `not-found` row reads "no such resource or path".

Change nothing else.
