  - **whoever next edits `server/api/test/contract.test.mjs`:** it compares response codes, response media types, security and tags, but not parameters, query, body and headers (E02-R07 review 1), and has not decided how annotation keys (`description`, `example`) compare;
  - **E10-R02:** the app requests `openid profile email` and the project audience scope (`urn:zitadel:iam:org:project:id:<project_id>:aud`), and a user's first request to the API must come while their login session is alive (Zitadel refuses a token at userinfo once its session is gone); a real login keeps its session;
  - **E02-R09 / `make token`:** the helper no longer deletes its test session (its 300 s lifetime ends it), so a token from `make token` works at Zitadel's own endpoints for five minutes, and a first request with it must come within that time;
  - **E08:** production sets `CALFLEX_OIDC_AUDIENCE` (the project ID) from configuration and leaves `CALFLEX_OIDC_BASE_URL` unset, so the API talks to the issuer's own origin; a changed project ID needs the value changed (or the file rewritten) because the API caches the audience until a token fails on it;
  - **E08:** the production Compose file and Caddyfile set `CALFLEX_TRUSTED_PROXY_HOPS=1` and keep Caddy's `trusted_proxies` empty. Left at its default 0 behind Caddy, every client shares one bucket of 300 requests per minute (the rate limiter, `CALFLEX_RATE_LIMIT_MAX` and `CALFLEX_RATE_LIMIT_WINDOW_SECONDS`, counts a request before the token is verified, 401s included). The buckets are in memory: a second API instance needs a shared store.
