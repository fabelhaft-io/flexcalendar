- **From the E12-R02 review, for later requirements:**
  - **E12-R01 (the wire spec):** neither `libsodium-wrappers` nor `-sumo` 0.8.4 exports an HKDF function (only the `crypto_kdf_hkdf_sha256_*` constants), and the standard build has no HMAC-SHA-256 either; `crypto_kdf_derive_from_key` (BLAKE2b) is in every build and byte-identical on the Dart VM, Android (API 37 `x86_64`) and Node. Choosing HKDF-SHA-256 means sumo plus a hand-built RFC 5869 over HMAC, or WebCrypto, and an ASCII `info`, because the Dart `sodium` API takes the HKDF info as a `String` (`docs/verification/crypto-libs-2026-10-12.md` §§ 4–5);
  - **E12-R03, E12-R04, E10-R01 (the Dart dependency):** `sodium_libs` is discontinued on pub.dev (`replacedBy: sodium`) and 4.0.1 only re-exports `sodium`; depend on `sodium` 4.1.1+2 directly. It builds libsodium 1.0.22 through a build hook, which `dart run` and `dart test` honour and `dart <file>.dart` does not. ADR 0001 § Libraries still names `sodium_libs`: the owner decides whether that line is amended;
  - **E10-R01 (the Android build):** the first Android build of a `sodium` app on the dev host took 446 s and downloaded NDK r28c (`28.2.13676358`) into the Android SDK; plan for that in CI and in a fresh dev setup;
  - **E12-R05 (cross-language vectors in CI) and Phase 5's `packages/crypto-ts`:** the probes in `infra/crypto-libs-check/` are run-once evidence, not gated by `make verify`; their `frozenValues`/`FROZEN_VALUES` are a ready seed for the frozen vectors. Pick sumo only if the spec needs HMAC (or ever Argon2id, which D-17 rules out); the standard build has every primitive the epic names.
