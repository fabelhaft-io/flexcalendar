- **From the E15-R02 reviews, for later requirements:**
  - **E05-R05:** the runner reads `spec/ical-fixtures/dst/cases.json` and derives the zone itself: the table carries no `VTIMEZONE`, and `ical.js` has no zone database, so a `TZID` without a definition silently becomes floating time. For a `daily-skipped` case it accepts `expected` or `alternative`, reports which matched, accepts nothing else and does not count the kind green while `ruling` is `pending`; for a `view-zone` case it compares the wall clock it would show to `expectedLocal`. `ical.js` 2.2.1 is **known wrong** on two single-time cases (`dst/README.md`, reproduced in review 1): a skipped local time gets the offset after the gap (`20260329T003000Z` for Berlin, the RFC says `20260329T013000Z`) and a repeated one gets the second occurrence (`20261025T013000Z`, the RFC says `20261025T003000Z`). The API must not hand a client an instant it computed from those two cases without normalising them, and must never "fix" the table to match. The table has one daily series per transition, not one long series across both; ask for the long one if the runner wants it;
  - **E10-R04, E09-R02, E11-R05 (the clients' runners):** the same contract as above, so each reads `ruling`, `alternative` and `expectedLocal` and not only `expected`. Dart's `timezone` package, `Intl` and `iCal4j` must each give the RFC's answer for a skipped and a repeated local time, which is not what `ical.js` gives;
  - **E12-R01:** the wire spec and its vectors pin the same two single-time answers as the table (`skipped` → offset before the gap, `repeated` → first occurrence; E04-R04's review raised it). The `daily-skipped` answer waits for the owner's ruling on RFC 5545 § 3.3.10 (`docs/reviews/follow-ups.md` § Open with the owner); do not freeze either reading in a vector before it;
  - **the owner's ruling on § 3.3.10, when it comes:** one commit removes `ruling` and `alternative` from the eight `daily-skipped` cases and the paragraph that explains them, keeps the chosen answer in `expected`, and adjusts the validator and its tests (`infra/scripts/dst-table.mjs`); every runner re-runs the table.
