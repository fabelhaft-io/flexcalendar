**A correction to review 1.** I wrote that an XML parser normalises `\r\n` to `\n` in report data. The implementer found the real cause and it is SabreDAV's: `CalDAV/Plugin.php:412` returns `str_replace("\r", '', $val)` for `calendar-data` in a `propFind`, so the service strips the carriage returns before the XML is built. The result (LF in reports, CRLF from `GET`) and the decision are the same; the comments and README now say the service does it.

**Security choices** (each was run, not read): every request carries a freshly signed `X-Calflex-Principal` (the first key, a new 16-byte nonce, `t` in seconds), signed over the path and query of the same `URL` object that is sent; the delegation keys are validated once (at least 32 bytes, canonical base64, unique ids) and never appear in an error; `redirect: 'manual'` with a redirect treated as an error, 10 s timeout, 4 MiB response cap, no retry of a signed request, no logging; errors carry a kind, the status and, for a `DAV:error`, the `cf:` element names only (the `cf:name` text only if it matches `[A-Z][A-Z0-9-]{0,63}`), never a body, URL or header; `node:crypto` is used for `createHmac` and `randomBytes`, for authentication only (INV-07 checks dependencies; `tsdav` 2.4.0 is MIT with `debug` and `xml-js`); ESLint and a grep test confine `tsdav`, the header, the origin variable and the keys to the adapter.

Follow-ups for other requirements are in `follow-ups.md`: **E05-R03 and E05-R04** (the adapter's `CalDavError` carries `kind`, `status` and the `cf:` element names only: map `cf:private-skeleton-only`/`cf:name` and `cf:unmapped-collection` to problem+json from there; a route that returns the raw `ical` uses `getObject`, because report data is LF-normalised); **E05-R08** (`syncChanges` hands the token to the caller; a token SabreDAV rejects is a `CalDavError` the route maps to 410); **E08** (`api-test` runs in CI only where Podman does, like `caldav-test`).

## Brief (condensed)

One adapter module, the only importer of `tsdav` and the only reader of `CALFLEX_CALDAV_ORIGIN` and `CALFLEX_DELEGATION_KEYS`; per-request signing through the `fetch` override tsdav accepts (static headers cannot sign a method, target and nonce); a small `forUser(userId)` surface (`makeCalendar`, `putObject`, `getObject`, `deleteObject`, `listObjects`, `syncChanges`); errors with a kind, a status and the precondition element names only; a lint rule and a grep test that confine tsdav; unit tests against the E03-R01 vectors; and, because the internal listener has no published port, an `api-test` compose service built from a `test` stage of the API image, run by `make test-api-caldav` and registered with the invariant checks.
