**The two report cases.** `listObjects` and `syncChanges` return the `calendar-data` of a multistatus; an XML parser normalises `\r\n` to `\n`, so the data comes back with LF while `getObject` returns the stored CRLF bytes. The tests expect CRLF from the reports. The adapter's own comment says `getObject` avoids "the XML round-trip", so the difference is known, just not tested. Decision for the open point: **report data is XML-normalised and the adapter says so; the exact stored bytes come from `getObject`.**

**The Makefile.** The new target replaced `.PHONY: test-caldav` with `.PHONY: test-api-caldav`; `test-caldav` is no longer phony (a file of that name would stop it). Both must be declared.

**Survivors.** A3: the default nonce (`randomNonce`) is never used by a test, which all inject theirs; A15: the fixed display name `Private calendar` that `makeCalendar` sends is only checked by the in-stack suite that never ran; E3: the lint test never puts the offending import under `server/api/src/` (the exemption widened to all of `src` passes); A9: the foreign-origin check in the signed fetch is unreachable through the public surface (tsdav does not leave the origin), so nothing can test it.

5. **`parsePreconditions` on untrusted bytes.** Parse at most the first 16 KiB of the body (a `DAV:error` from the service is a few hundred bytes), and replace the tag regex with a linear scan or one that cannot backtrack across the whole input. 6. **Tests for the survivors:** the default nonce (two default adapters sign two requests: 22 base64url characters, never equal); `makeCalendar` sends exactly the display name `Private calendar` and nothing else (a recording transport); the lint test places the offending import in `server/api/src/` outside the adapter and in `server/api/test/` and expects the rule in both; export `signedFetchFor` (or make it reachable) and test that a foreign-origin URL is refused and a relative one is resolved against the origin.

## Brief (condensed)

One adapter module, the only importer of `tsdav` and the only reader of `CALFLEX_CALDAV_ORIGIN` and `CALFLEX_DELEGATION_KEYS`; per-request signing through the `fetch` override tsdav accepts (static headers cannot sign a method, target and nonce); a small `forUser(userId)` surface (`makeCalendar`, `putObject`, `getObject`, `deleteObject`, `listObjects`, `syncChanges`); errors with a kind, a status and the precondition element names only; a lint rule and a grep test that confine tsdav; unit tests against the E03-R01 vectors; and, because the internal listener has no published port, an `api-test` compose service built from a `test` stage of the API image, run by `make test-api-caldav` and registered with the invariant checks.
