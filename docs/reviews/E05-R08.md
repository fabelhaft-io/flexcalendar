### The fresh stack (`make dev-reset`, `dev-build`, `migrate`, `seed`, tokens not printed), through Caddy with Caddy's CA, no `-k`

This stands in for the suite that could not load. An empty calendar: initial load → `[]` and a token; a poll with its own token → `[]` and the **same** token. Two creates → both listed with `etag`; an empty poll after them → the same token again; an update → that one object; a delete → `{"uid":…,"deleted":true}` with no `etag`; the initial load afterwards → the one live object. **Rejected tokens, all `410` `application/problem+json`:** not a token, an empty `since`, `since` given twice, another calendar's token, a number ahead of the collection (`:99999`), a 20-digit number. Number 0 is accepted and answers the current state. A stranger and `/calendars/not-a-uuid/changes` → `404`, no token `401`, `POST` → `405`. No token or query string in the API log.

### Independent checks

- **10 mutations** (each restored): another calendar's token accepted; a number ahead of the collection accepted; SabreDAV's own refusal not a 410; a tombstone carrying an `etag`; the `uid` always taken from the name; a malformed token answered 404; the first change of a batch dropped; the empty-poll token moved ahead — all **killed** by a named test. **Survives (C8):** logging the client's `since` (`request.log.info({ since: raw })`) breaks nothing, so the log test never sends a token.
- **The order of two calls.** When the report is empty the route asks `currentSyncToken` (a second request, the `PROPFIND`) and **returns that number as the new token**. The `REPORT` and the `PROPFIND` are two requests: a change that lands between them moves the collection from `n` to `n+1`, the report says "nothing since `n`", the `PROPFIND` says `n+1`, the client stores `n+1`, and that change is never reported. No test models it.

### Fix requests (one run)

1. **The in-stack suite must load in the `api-test` image.** That image installs production dependencies only (`pnpm install --prod`, `server/api/Dockerfile`), and `yaml` is not among them. `test/integration/changes.test.mjs` imports `test/support/problem.mjs`, which reads the spec with `yaml`. Make the integration suite stand on `node:` modules, `pg` and `src/`, and check the problem bodies with plain assertions on `type`, `status` and the absence of anything else. Then add a database-free unit test over `test/integration/*.test.mjs` that reads each file's imports and fails on a bare specifier that is not in `server/api/package.json`'s `dependencies` (and on an import of `test/support/problem.mjs`), so this cannot reach the stack again.
2. **The token comes from the `REPORT`, never from a later request.** In the empty case return the number the report itself carries (`report.syncToken`, which is what SabreDAV computed together with the changes), and use `currentSyncToken` only to refuse a token that is ahead of the collection. Model the race in the double (a hook that advances the collection between the report and the `PROPFIND`) and test that the returned token is the report's and that the next poll returns the change. I keep the extra `PROPFIND` rather than a signed token: it costs one tiny request on an empty poll only, and a key to manage is worse.
3. **Kill C8.** The log test sends a good token and a rejected one (and the initial load), and asserts that neither the string nor its decoded `<calendar id>:<n>` form appears in the captured log.

Change nothing else.
