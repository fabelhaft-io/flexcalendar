**Security-relevant choices for the human approval** (each was run, not read):

1. **Validation:** `jose` 6.2.12 with `algorithms: ['RS256']`, `iss` equal to `CALFLEX_OIDC_ISSUER`, `aud` containing the audience, `exp`, `nbf` and `sub` required, 5 s tolerance, `sub` of 1 to 255 characters. Exactly one `Authorization: Bearer` header (the scheme is case-insensitive), at most 8 KiB, three base64url segments, never from the query string; anything else is a 401 before any network call. `alg: none`, HS256 signed with the public key, an unknown or wrong key, an opaque token, a future `nbf`, a wrong issuer or audience: all the same 401.
2. **One hook, no exceptions but one:** a global `onRequest` hook protects every route; only `GET`/`HEAD` on exactly `/healthz` skips it. Unknown routes and methods are 401 first, 404 after a valid token. `/healthz` touches no database and no IdP.
3. **One response:** every authentication failure is the identical 401 (`{"error":"unauthorized"}`, `WWW-Authenticate: Bearer`, `Cache-Control: no-store`), no reason code anywhere; no token, header, claim or userinfo field is logged or echoed (the logger stays off, E05-R10 owns it). The pool's error handler is silent for the same reason.
4. **Reaching the IdP:** discovery, the JWKS and userinfo are the only three calls, all `GET` through `node:http(s)` (so a custom `Host` survives), without redirects, 5 s, 1 MiB. Discovery's `issuer` must equal ours; `jwks_uri` and `userinfo_endpoint` must be same-origin with the issuer and are re-rooted on `CALFLEX_OIDC_BASE_URL`. RSA signing keys with a `kid` only; cached 10 minutes; an unknown `kid` refetches at most once per 30 s; with cached keys an outage does not stop validation, with none the answer is 503.
5. **Audience:** `CALFLEX_OIDC_AUDIENCE`, else the first line of `CALFLEX_OIDC_AUDIENCE_FILE`; neither: 503 for everything but health. The file is written by `zitadel-config apply` (mode 0644, the project ID only, atomically, never by `plan`), lives in a volume the API mounts read-only, and is re-read at most once per 5 s after an audience mismatch.
6. **First sight:** only for a valid token whose `sub` has no row: one userinfo call with the caller's own token, `email_verified` must be `true` (403), userinfo's `sub` must equal the token's (502), a failure is 502, a taken handle or e-mail is 409, and none of those creates a row; the insert is `ON CONFLICT (idp_subject) DO NOTHING`, so two simultaneous first requests make one. No profile sync afterwards.
7. **The helper no longer deletes its session** (E02-R09 behaviour change, local and staging only): Zitadel refuses a token whose session is gone at its own endpoints, userinfo included. The 300 s lifetime ends the session; a first request with a helper token must come within five minutes; a user who already has a row never calls userinfo. A token from a real login has a live session.
8. **Dependencies and files:** `jose` (MIT) is the only new dependency, with its INV-07 entry; the API image reads nothing but its environment and the audience file. `GET /me` returns the caller's own `id`, `handle` and `email` and nothing else.

What the API does not do, and that is deliberate: rate limiting of 401s, CORS, and logging (E05-R10, E08).

Follow-ups for other requirements are in `follow-ups.md`: **E10-R02** (the app requests `openid profile email` and the project audience scope, and a user's first request must come while their login session lives); **E05-R03 and later** (the hook sets only `request.user.sub`; `GET /me` resolves the row. A route that needs `users.id` must resolve it through the same first-sight function, not its own); **E05-R10** (`GET /me` can answer 500 `{"error":"internal_error"}` when the database fails and the spec declares no 5xx; the contract test does not compare parameters, query, body and headers yet, nor annotation keys); **E08** (production sets `CALFLEX_OIDC_AUDIENCE`, leaves `CALFLEX_OIDC_BASE_URL` unset, and a changed project ID needs the value changed or the file rewritten); **the orchestrate skill** (`make dev` does not rebuild images: a stale API image from before the requirement made review 1's first result meaningless, so reviews must run `make dev-build`).

## Brief (condensed)

Three owner decisions: the expected audience is the Zitadel project ID, from `CALFLEX_OIDC_AUDIENCE` or a file `zitadel-config apply` writes into a shared volume (503 until one exists); handle and e-mail on first sight come from the issuer's userinfo, called once with the caller's token (unverified e-mail 403, mismatching `sub` 502, a taken handle or e-mail 409, nothing created on a failure); the one authenticated route is `GET /me`. Validation: `jose` 6.2.12 with RS256 only, `iss`, `aud`, `exp`, `nbf` and `sub` required, 5 s tolerance, an in-process JWKS fetched through `node:http(s)` (so the `Host` header survives), same-origin endpoints re-rooted on the base URL, an unknown `kid` refetching at most once per 30 s, one global `onRequest` hook for everything but `GET`/`HEAD /healthz`, one fixed 401. Tests against a stub IdP that signs the negative tokens itself. My brief's reviewer list left out `make migrate`.
