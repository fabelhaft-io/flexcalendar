### Validation (`server/api/src/`, `jose` 6.2.12, exact pin; MIT, Node 24)

- Header `Authorization: Bearer <token>`: scheme case-insensitive, exactly one header, token at most 8 KiB, never from the query string. Anything else, or not three base64url segments (an opaque token), is 401 **before any network call**.
- `jwtVerify` with `algorithms: ['RS256']` only, `issuer` exactly `CALFLEX_OIDC_ISSUER`, the audience, `exp` and `nbf` required, `clockTolerance` 5 s, a non-empty `sub` of at most 255 characters. The keys are an in-process set built from the JWKS; do not use `createRemoteJWKSet` (it fetches with the global agent and cannot pin the base URL).
- **Discovery and JWKS.** `CALFLEX_OIDC_BASE_URL` (default: the issuer; locally `http://zitadel-api:8080`) is where requests go. Send `Host: <issuer host:port>` when the base differs from the issuer. Fetch `<base>/.well-known/openid-configuration`, require its `issuer` equals `CALFLEX_OIDC_ISSUER`, take `jwks_uri` and `userinfo_endpoint`, require each to be same-origin with the **issuer**, then re-root them on the base URL. `redirect: 'error'`, 5 s timeout, 1 MiB body cap, RSA JWKs only. Cache the keys 10 min. An unknown `kid` refetches at most once per 30 s (a flood of random `kid`s must not become a flood of fetches). With cached keys and Zitadel down, keep validating; with none, 503.
- Every failure is the same 401 (`WWW-Authenticate: Bearer`, `Cache-Control: no-store`, fixed body `{"error":"unauthorized"}`); no reason code in the response or the logs. No token, header, claim or userinfo field is ever logged or put in an error (the logger stays off; E05-R10 owns logging).
- One global `onRequest` hook protects **everything but `GET`/`HEAD /healthz`**, unknown routes and other methods included (401 first, 404 after). `request.user = { id, sub }`. `/healthz` stays database-free.

### Tests (`server/api/test/`, Postgres through `support/postgres.mjs`)

The negative tokens are signed by a key the **test serves as its own JWKS** from a stub HTTP server (discovery, JWKS, userinfo), never by Zitadel; point `CALFLEX_OIDC_BASE_URL` at it. Cases: a valid token → 200 and the first request creates the row (and a second request does not call userinfo); expired; wrong audience; `alg: none`; HS256 signed with the public key's bytes; signed by an unknown key; opaque; `nbf` in the future; wrong issuer; missing `sub`; two headers; query-string token; all → 401 with the identical response. Unconfigured audience → 503. Rotation: serve key A, accept, switch the stub to key B, a token with B's `kid` is accepted **without restart**, an unknown `kid` is rejected and the stub saw at most one refetch per window. First-sight: unverified email, mismatching userinfo `sub`, userinfo down, duplicate e-mail, two simultaneous first requests (one row). Assert the response and the captured stderr contain no part of the token. Use opaque test blobs and `Buffer`s; the tests need `node:crypto` to sign: keep test keys under `test/` only (INV-07 scans `src/`).
