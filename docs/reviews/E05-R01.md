**The helper's tokens do not work at userinfo (a required fix).** `make token` finishes by deleting its test session, as E02-R09 designed it. A Zitadel access token whose session is gone passes every local check (signature, `iss`, `aud`, `exp`, `nbf`) but is refused by Zitadel itself: userinfo answers `401 access_denied`, "access token invalid", through Caddy as well as on the internal URL. The API did exactly what it should (a 502, no row). Keeping the session alive made the identical token work. A token from a real login has a live session, so this only affects the helper, but the Accept ("a token from the helper → 200") depends on it.

**A Postgres restart crashes the API (a required fix).** `pg.Pool` has no `error` listener, so a dropped idle connection is an unhandled `error` event: `podman restart` of Postgres after one warm request took the API process down (`RestartCount` 0 → 1) with a stack and the client object printed to the log. The dump holds the user, database and host but no password.

**Mutations that survive.** Auth code (21): the `exp` (O3) and `nbf` (O4) requirements, a tolerance of 3000 s instead of 5 s (O6: the tests use ±3600 s, so only far-off times are tested), the 255-character `sub` bound (O7), discovery's `issuer` comparison (O8) and the same-origin check on `jwks_uri` and `userinfo_endpoint` (O9), cached keys surviving a failed refresh (O11), non-RSA keys (O12) and keys without a `kid` (O16) being ignored, the 1 MiB cap (O14) and the status check (O15) of the IdP client, the 503 for an IdP outage with no cached keys (A13), the audience re-read after a mismatch at the hook level (A14), an empty `preferred_username` (A17), the health exemption by prefix (A2), the scheme's case (A3), and the oversize and character rules of the token (A5, A6: they end in a 401 anyway, so only "no network call" would show them). Equivalent or defensive, no case needed: A18 (the hook always sets `sub`), O5 (two layers check `sub`), O17 (`jose` rejects a non-RS256 key by its type). Others: the audience file written without a rename (I2: not observable), an empty project ID written (I5), and an untagged `/me` (C5: the contract test does not look at tags).

### Fix requests (run 2)

1. **Helper.** `infra/zitadel/token.mjs` stops deleting the test session; the 300 s lifetime stays and ends it. Update its stub and test (the stub enforced the deletion), and say in `infra/zitadel/README.md` that a token from `make token` is usable at Zitadel's own endpoints, userinfo included, only while that session lives, so a first request with it must come within five minutes (a user who already has a row never calls userinfo).
2. **Pool.** Attach an `error` listener to the pool (no logging, no dump; a dropped idle client is replaced by the pool), in a function you can test: create the pool in `store.mjs`, and test that an `error` emitted on it does not throw.
3. **README.** State what I observed: `preferred_username` for the seeded users is the plain login name (`alice`), and the stack needs `make migrate` before `GET /me`.
4. **Tests for the survivors,** each shown to fail without the check:
   - tokens without `exp`, without `nbf`, a `sub` of 256 characters; expired by 30 s and `nbf` 30 s ahead are 401, and 2 s either way is accepted (the tolerance, both sides);
   - the malformed-token table on a **fresh** API leaves the stub's discovery and JWKS counters at zero (oversize, opaque, wrong segment count and characters never reach the network);
   - `/healthz/`, `/healthz/x`, `//healthz`, `/healthz;x`, `/HEALTHZ` are 401 and `/healthz?x=1` is 200; the scheme `bearer` and `BEARER` is accepted;
   - no cached keys and the IdP down is 503; a token with a known `kid` still verifies when the IdP is down, and an unknown `kid` then is 401;
   - at the hook, an audience file that appears or changes after boot is picked up without a restart (start with a file naming another project, then rewrite it), and a token with the old audience is 401 afterwards;
   - unit tests of `createOidcClient` with its injectable `request` and `now`: a failed refresh after the key TTL keeps the cached keys; discovery with another `issuer` is refused; a `jwks_uri` or `userinfo_endpoint` on another origin is refused; JWKs that are not RSA, have no `kid`, have `use` other than `sig` or `alg` other than `RS256` are ignored; and `getJson` against a local server rejects a 500, a body over 1 MiB and a redirect;
   - an empty or blank `preferred_username` or `email` from userinfo is 502 and creates no row;
   - the contract test fails for an operation without a tag;
   - `infra/zitadel`: an empty `project_id` makes `apply` fail and writes no file.

Change nothing else. Run `format:check`, `lint`, `typecheck` and the database-free tests; list the stack commands for me as before.

## Brief (condensed)

Three owner decisions: the expected audience is the Zitadel project ID, from `CALFLEX_OIDC_AUDIENCE` or a file `zitadel-config apply` writes into a shared volume (503 until one exists); handle and e-mail on first sight come from the issuer's userinfo, called once with the caller's token (unverified e-mail 403, mismatching `sub` 502, a taken handle or e-mail 409, nothing created on a failure); the one authenticated route is `GET /me`. Validation: `jose` 6.2.12 with RS256 only, `iss`, `aud`, `exp`, `nbf` and `sub` required, 5 s tolerance, an in-process JWKS fetched through `node:http(s)` (so the `Host` header survives), same-origin endpoints re-rooted on the base URL, an unknown `kid` refetching at most once per 30 s, one global `onRequest` hook for everything but `GET`/`HEAD /healthz`, one fixed 401. Tests against a stub IdP that signs the negative tokens itself. My brief's reviewer list left out `make migrate`.
