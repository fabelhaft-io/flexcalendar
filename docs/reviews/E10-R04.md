### What to build

1. **The device zone** read through a native call: `flutter_timezone` (pub.dev 5.1.1, 2026-10-03; pin exactly). Initialise the tz database once at start (E10-R01 already has `initializeAppTimeZones()` in `lib/src/timezones.dart`; extend it, don't add a second loader) and set the device zone as the `timezone` package's local location; an IANA name the database doesn't know falls back to UTC, visibly (a log line without user data, and a state the UI can show).
2. **A zone layer in the domain code** (`lib/src/…`): conversion between the API's event time shapes and `TZDateTime` — `{date}`, `{utc}`, `{local: "YYYYMMDDTHHMMSS", tzid}` (from-E05-R09; the zone name is an exact-spelling IANA name; link names such as `Asia/Calcutta` are accepted, `europe/berlin` or a Windows name is not) — with RFC 5545 § 3.3.5's answers for a local time that doesn't exist (the offset **before** the gap) or occurs twice (the **first** occurrence). The `timezone` package follows Java/Joda (the offset after the gap, the second occurrence); `packages/crypto_dart`'s `instantOf` (E12-R03, PR #101, not merged yet) shows the correction; don't depend on that package, write the app's own and test it. All-day is a date, never a midnight instant (INV-04).
3. **The guard against `DateTime` arithmetic in the domain layer:** a test (or a custom lint) that fails when a file under the domain directories calls `DateTime` arithmetic or constructors that read the device's local zone (`DateTime.now()`, `.add(`/`.subtract(`/`.difference(` on a plain `DateTime`, `DateTime(…)` local constructors, `.toLocal()`), with an allow-list that names each exception and why. Prove it fails on a planted bad file (in a test fixture, not in `lib/`).
4. **DST widget tests** for the E15-R02 dates in Europe/Berlin, America/New_York, Australia/Sydney and Asia/Kolkata, **read from `spec/ical-fixtures/dst/cases.json` itself** (never a copy; from-E15-R02: read `expectedLocal` as well as `expected`, and compare a `daily-skipped` case like any other, per the § 3.3.10 ruling). Report how many cases each zone contributed; a zone with no case fails the test. Add a small widget that renders an event time in the device zone, and test it across each transition with the device zone set to each of the four.
