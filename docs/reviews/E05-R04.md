## Brief for run 1

### What is already true

- `server/api/src/calendars.mjs` is the pattern: routes declared in `spec/openapi.yaml` first, `resolveUser` for `users.id`, `calendars.findMembership(id, userId)` for the role (non-member → the 404 an unknown id gets), ids checked against the canonical-UUID shape **before** the store is asked (Postgres raises `22P02` otherwise), `sendProblem` / `sendCalDavProblem` for every refusal, and `adapter.forUser(userId, { requestId: request.id })`. A CalDAV `401` is a `502`, never the caller's 401. The adapter has `putObject(calendarId, name, ics, { ifMatch, ifNoneMatch })`, `getObject`, `deleteObject(…, { ifMatch })`; `getObject` returns the stored bytes, `listObjects` LF-normalises (use `getObject` for the raw `ical`). A write needs the `calendars` and `calendar_members` rows to exist (E05-R03 creates both).
- The write guard (E03-R09, `server/caldav/src/PrivateSkeleton.php`) accepts a Private object only as a skeleton: `UID`, `DTSTAMP`, `DTSTART`/`DTEND`, `RRULE`/`RDATE`/`EXDATE`, `RECURRENCE-ID`, `SEQUENCE`, a `VALARM` with `DESCRIPTION:Reminder`, **one `X-CALFLEX-ENVELOPE-SHA256` per `VEVENT`**, and the structural properties; no `SUMMARY`, `DESCRIPTION`, `LOCATION`, `ATTENDEE`. `spec/ical-fixtures/ours/` holds six accepted examples and `synthetic/` seven refused ones.
- E15-R01 landed the harness `server/api/test/ical-roundtrip.mjs`: `checkRoundTrip({ id, text, roundTrip })` over every fixture, two passes (through `ical.js` and on raw content lines), symmetric (an **added** component, property or parameter fails), no value in a failure. **This requirement's module plugs in as `roundTrip` and the unit test the Accept line asks for is that call.**
- `ical.js` 2.2.1 is the only recurrence authority. It has no zone database, and it is **wrong** on a skipped and on a repeated single local time (`spec/ical-fixtures/dst/README.md`). E05-R09 owns time zones: **until it lands this requirement accepts `Z` and `VALUE=DATE` times only**, and a write carrying a `TZID` is a 422. Reading and round-tripping an object that already has a `TZID` or a `VTIMEZONE` must keep it untouched (INV-02).
- Spec: `docs/epics/E05-api-core.md` § E05-R04 and the paragraph above the requirements; INV-02, INV-03, INV-04, INV-05, D-06, D-07; `docs/06` for the invariants.

### What to build (choices marked **mine** are the orchestrator's; the epic leaves the shape open; say in the handoff if you deviate)

1. **The read-modify-write module** `server/api/src/ical-rmw.mjs`: `parse`, `patch` and `serialise` on `ical.js`, which preserves **every** component, property and parameter it does not understand, `X-` ones and a `VTIMEZONE` included (INV-02). Unit tests: `checkRoundTrip` over the whole corpus with a no-op patch as `roundTrip`; then, per fixture, a patch of a known field changes that field and nothing else (use the harness's comparison). A module that adds or drops anything fails.
2. **Routes, mine:** `POST /calendars/{calendarId}/events`, `GET`, `PATCH` and `DELETE /calendars/{calendarId}/events/{uid}`. Single-object CRUD only: the windowed list with expansion is E05-R05, the delta is E05-R08, and recurring-edit intents are E05-R06/R07. The object name in CalDAV is `<uid>.ics`.
3. **Create, mine:** the client sends **fields**, not iCalendar text (INV-05: the client never writes `EXDATE`/`RECURRENCE-ID`; the API builds the object): `start` and `end` (`{date}` for all-day, `{utc}` as `YYYYMMDDTHHMMSSZ` for timed; `end` optional), `rrule` (a string, validated by `ical.js`, create only), `alarm` (`{trigger}`, an ISO duration; the API writes `ACTION:DISPLAY` and `DESCRIPTION:Reminder`), `envelopeSha256` (64 lowercase hex). The API mints the `UID` (`crypto.randomUUID()`, INV-03: tested on the create path) and `DTSTAMP`, writes with `If-None-Match: *`, and answers `201` with `Location` and `ETag`. On a Private calendar a content field (`summary`, `description`, `location`, `attendees`) is a 422 with the fixed `invalid-input` body, and so is a missing `envelopeSha256`. Phase 4 adds the Shared content fields; the module must already keep them if they are on the object.
4. **Update, mine:** `PATCH` takes the same fields (never `rrule`, `exdate`, `recurrenceId` or `uid`: those are 422, a recurring edit is an intent), needs `If-Match` (**428** without, as for calendars) and forwards it to CalDAV; the API reads the stored object with `getObject`, applies the patch with the module, bumps `SEQUENCE` and `DTSTAMP`, and `PUT`s with the same `If-Match`. A `412` from CalDAV answers `412` **with the current representation**: re-read and return it as the `current` member of the problem (add `current` to the `Problem` schema and the spec as an optional object; nothing else in a problem may carry event data, and on a Private calendar the representation is the skeleton). `DELETE` needs `If-Match`, answers `204`, and `404` for an unknown uid.
5. **Representation, mine:** `{uid, etag, ical, parsed}`. `ical` is the stored text, byte for byte (`getObject`); `etag` is CalDAV's, passed through as the `ETag` header too; `parsed` is `{uid, start, end, rrule, alarm, sequence, envelopeSha256}` of the master `VEVENT`, nothing else (no override list, no content). An object with several `VEVENT`s (overrides) is readable and its master is `parsed`; `PATCH` on the master keeps the overrides byte-identical.
6. **Errors:** a write the guard refuses reaches the client as problem+json naming the property and never its value (`sendCalDavProblem`); a `uid` outside the canonical-UUID shape is the 404 an unknown one gets; a `uid` over 200 characters or one that is not UUIDv4 never reaches CalDAV (E03-R10's note: `calendarobjects.uid` is `VARCHAR(200)`); roles: `owner` and `editor` write, `viewer` reads (403 on a write), a non-member gets 404.
7. **Tests:** the module (above); the routes through the real app with the in-memory store and a fake adapter that behaves like the guard (extend `test/support`); a hostile-exception case; a test that a created `UID` is UUIDv4; the 412 body holds the current representation and nothing from the rejected request; no content field, envelope hash or object text reaches a log (use a canary). In the stack (`server/api/test/integration/`, run by `make test-api-caldav`): create, read back byte-identical, patch with a stale `If-Match` (412 plus `current`), patch with the right one, delete, and a refused write whose marker reaches neither body nor log.
