## What to build

1. **`sabre/dav` 4.7.1**, exact pin (`"sabre/dav": "4.7.1"`, no caret), in `composer.json` and `composer.lock`. Packagist resolves it to commit `f36f002dce082e1d425c4a0dc8c71a6b176c3b07`, the `commit` in `server/api/sabredav/record.json` (fields `package`, `tag`, `commit`). It installs on PHP 8.4 (`composer require sabre/dav:4.7.1` on PHP 8.4 with the repo's `composer.json` and platform 8.4.0 installed 68 packages with the dev tools and ended with "No security vulnerability advisories found"). Locked runtime packages: sabre/event 5.1.9, http 5.1.13, uri 2.3.4, vobject 4.6.1, xml 2.2.11, psr/log 3.0.2.
2. **The record test** (unit, host-side): `composer.lock`'s `sabre/dav` `version` and `source.reference` equal the record's `tag` and `commit`. Make the comparison a function the test also feeds a tampered copy, so the test is shown to fail on a difference. Don't edit the real files to prove it.
3. **Image**: `dunglas/frankenphp:1.13.0-php8.4.26-alpine` (exists; PHP 8.4.26 ZTS, Caddy 2.11.7). **Classic mode only**: no `worker` directive anywhere; add a `check-stack` assertion and a unit test that fail on one. `RUN install-php-extensions pdo_pgsql` works on it (built today: libpq 18.6). It already has dom, simplexml, mbstring, ctype, iconv, json, pcre, xmlreader, curl. `composer` comes from `docker.io/library/composer:2.10` (exists) in a build stage with `--no-dev`; a `test` stage adds the dev dependencies. Run as a non-root user: `/data` and `/config` are root-owned (point `XDG_DATA_HOME` and `XDG_CONFIG_HOME` somewhere writable), and the binary carries `cap_net_bind_service`. Keep `mem_limit: 256m` (`check-stack` requires one) and set `num_threads` explicitly; the reviewer measures RSS under the suite.
4. **Two listeners, two document roots**: public `:8080` (what Caddy routes) and internal `:8081`, in a Caddyfile for FrankenPHP under `server/caldav/` (not `infra/dev/Caddyfile`, the outer proxy). `vendor/` and `src/` sit outside both roots, nothing is served statically, and every path reaches the front controller. **The public entry never loads the delegation classes and never reads `HTTP_X_CALFLEX_PRINCIPAL`**: a unit test shows that the public entry file and every class it loads don't mention the header name. It answers `GET /healthz` (the compose probe) without SabreDAV or the database, and 401 for everything else (the `/.well-known/caldav` redirect is R02). Its responses are byte-identical with no header, a valid one and garbage (headers apart from `Date`, status, body).
5. **Confine the internal listener**: add a Compose network that only `caldav`, `api` and the one-off test service join, no `ports:` entry for 8081, no Caddy route (add `check-stack` assertions for all three). `caldav` is also on `stack`, and a listener on `0.0.0.0` is then reachable from every container there. Bind it to the dedicated network's address (an `ipam` subnet and a static `ipv4_address`, `bind` in the Caddyfile) unless Podman cannot do that. If you can't, say so in the PR: the HMAC would be the only barrier on `stack`. Give it its own alias (for example `caldav-internal`). Caddy also drops `X-Calflex-Principal` on every public route (`request_header -X-Calflex-Principal`), as a second layer; the entry still ignores it.
6. **Delegation backend** (format fixed in the requirement; E05-R02 writes the TS side). Strict: exactly the six fields, `v=1`, no duplicates, no extras; `p` a UUID, `t` digits only, `n` 22 base64url characters, `s` 43. Order: parse, known `k`, signature (`hash_equals`), `|now − t| ≤ 60`, nonce insert, `users` row. **An unauthenticated request writes nothing to the database.** Every failure is the same 401 (same body, no reason in it, `Cache-Control: no-store`); the log gets a coarse reason code and never a header value, signature, nonce or request body. `METHOD` is the real method (no override header) and `request-target` is `REQUEST_URI` as sent. Prune with `DELETE … WHERE expires_at < now()`; the TTL is 120 s. Keys from `CALFLEX_DELEGATION_KEYS`: each at least 32 bytes after base64 decoding, ids unique; absent or invalid means every internal request fails closed, and the error never prints key material. Compose gives `caldav` a dev-only default key and `.env.example` a line.
7. **SabreDAV server**: CalDAV, ACL, Sync and PropertyStorage plugins only; no Browser (HTML UI), Locks, Sharing, Scheduling, Notifications, ICS export or CardDAV. Backends use the PDO classes with the table-name properties pointing at `sabredav.*`; the service's own reads are `public.users` and so on. `lastInsertId` is called with `<table>_id_seq`: check that it works with a schema-qualified table property rather than assuming it. Connection from `CALFLEX_DATABASE_URL` (`postgresql://`; passwords are URI-encoded, so `rawurldecode`), exceptions on, emulated prepares off. The principal backend reads `public.users` and is read-only. **SabreDAV's defaults leak the user directory** (checked in the vendored source): `DAVACL\Plugin::$allowUnauthenticatedAccess = true`, `$hideNodesFromListings = false`, and `AbstractPrincipalCollection::getChildren()` lists every principal the backend returns. Set the first false, the second true, and have the backend return only the acting principal. Another user's `/principals/<id>/` and `/calendars/<id>/` must be 404. Don't build R08: until it lands, SabreDAV's own `principaluri` ownership applies, and MKCALENDAR needn't consult `public.calendars`. Say so in the PR.
8. **Gates must see the new code.** `format:check`, `lint` and `typecheck` today name `public` only. Cover `src`, the entries and the tests (a loop over every `*.php` for the lint step). `composer test` runs on the host in the component job with no stack: it runs `tests/Unit` only. The suite is `tests/Integration`, never reachable from that script.
9. **INV-07**: adding `sabre/dav` makes `node infra/scripts/invariants.mjs INV-07` fail (checked on a scratch copy). Add exact entries to the `platform` map of `infra/scripts/invariant-dependencies.json`, each with its own honest reason: `ext-ctype`, `ext-curl` (sabre/http), `ext-date`, `ext-pcre`, `ext-simplexml`, `ext-spl`, `ext-xmlreader` (sabre/xml), `lib-libxml`. `ext-xmlwriter` has an entry already. The base image also compiles in `sodium`, which the gate can't see: the code uses only `hash_hmac`, `hash_equals` and `random_bytes`.
10. **Test signer and vectors**: the signer is test code (autoload-dev), absent from the image. Add `tests/Fixtures/delegation-vectors.json` with at least three vectors (a query string and a percent-encoded target among them) for E05-R02 to reuse. The reviewer recomputes them independently.

## The integration suite

- Place: `tests/Integration`, PHPUnit, over the internal listener. Cover every Accept bullet, each of the nine 401 cases, and per-user isolation (user A cannot read or write B's home).
- Run: a one-off Compose service `caldav-test` (profile `test`, like `seed` and `migrate`), built from the `test` stage, joined to `stack` and the internal network (the one stated exception to "only the API and CalDAV join"). Not `exec` into `caldav`: that image has no PHPUnit. `make test-caldav` depends on `migrate` (`make dev` doesn't migrate, and the service must come up healthy on an empty database: `/healthz` touches nothing) and runs `$(COMPOSE) --profile test run --build --rm -T caldav-test`.
- Register: `infra/scripts/verify/invariants/E03-R01.json`, `[["make","test-caldav"]]`. E02-R04 says later requirements register with `verify-invariants` and `verify-corpus` instead of editing `make verify`, and the corpus is for iCalendar round trips. CI runs this registry with the stack in the cross-cutting and full jobs; a change under `infra/` selects the full run. Update `infra/scripts/verify/invariants/README.md` (it says its checks need no stack). The suite's budget is a few minutes of the nine-minute `make verify` cap; report the time.
- Roles: seed `users`, `calendars` (a Private row needs a non-null `meta_envelope`: fixed placeholder bytes, never real ciphertext) and `calendar_members` as `calflex_api`, the role that writes them in production; assert on `delegation_nonces` as `calflex_caldav`; never as `calflex_migrate` or the bootstrap login. `calflex_caldav` has `SELECT` only on those three tables. Use fresh UUIDs per run, write `'private'` as a literal (E04-R03 changes the column type beside this run), and delete what the run created.
- Logs: put canary strings into the rejected header values and the bodies; after the run the Make target greps `$(COMPOSE) logs caldav` and fails if one appears, or if the logs can't be read.
- Event data in tests is invented. A recurring event has `DTSTART;TZID=Europe/Berlin` with its `VTIMEZONE` (INV-04), and the time-range query hits an instance, not the master.
