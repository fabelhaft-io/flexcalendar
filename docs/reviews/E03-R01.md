## Fix requests

1. **`make dev` fails depending on start order.** `caldav` has the static address `172.30.91.2` on `delegation`, but `api` joins it without one, takes `.2` when it starts first, and `caldav` then cannot start. CI passed by chance. Make the allocation deterministic: an `ip_range` for the dynamic pool that excludes the static addresses, or a fixed address for every member (`api`, `caldav-test`). Add a `check-stack` assertion for the property you pick. Report the result of at least 8 `make dev-reset && make dev` cycles from empty volumes.
2. **Fix `ServiceTest`.** In another user's home, `MKCALENDAR` answers 409, as it does in a nonexistent home; that is correct and leaks nothing. Replace the hard-coded status: for each of `PROPFIND` and `MKCALENDAR` in B's home, and for `GET`, `PUT`, `DELETE` and `PROPFIND` on a calendar object of A's as B, assert the status and body are equal to the same request against an id that exists nowhere. Today the suite checks only A looking at B.
3. **`Service::run` replaces SabreDAV's error mapping.** It calls `invokeMethod()` and answers every exception with `text/plain` "DAV request failed", dropping the `DAV:error` document that `Server::start()` builds from the exception's `serialize()`, and the exception's `getHTTPHeaders()` (observed: an invalid iCalendar `PUT` gives 415 with a plain-text body). E03-R09 needs a 403 with the `<cf:private-skeleton-only/>` precondition in that document, and RFC 4791 preconditions need it too. The wrapper's reason (keep exception messages, traces and class names out of responses) stands. So emit `application/xml` with an `DAV:error` element carrying only what `serialize()` adds, and the headers, and nothing from the message. Add a test whose exception carries an element or a header (the 412 on `If-None-Match: *` carries `<s:header>If-None-Match</s:header>` in SabreDAV's document; a 405 carries `Allow`), asserting that element or header is present and the message text is not.
4. **Version disclosure.** Both listeners send `X-Powered-By: PHP/8.4.26` and `Server: FrankenPHP Caddy`, and the 207s `X-Sabre-Version: 4.7.1`. Set `expose_php=Off` in the image, `Server::$exposeVersion = false`, and drop `Server` in the Caddyfile. Assert the absence on both listeners.
5. **Log reasons.** The brief asked for a coarse reason: every denial logs `delegation_denied`, and so do database and key-configuration errors. Use fixed codes per class (missing or malformed, unknown key, signature, skew, replay, unknown principal) and a separate `delegation_error` for exceptions. The response stays the same 401. Have `verify()` return the reason and unit-test it.
6. **Tests that survive mutation.** Add a vector for a non-canonical `s` or `n` (the same bytes with a different last character; it must fail); a `CALFLEX_DELEGATION_KEYS` entry with an empty key id (must fail closed); a `check-stack` assertion that `delegation` has `internal: true`, or drop the option.
7. **Unrequested edits in `compose.yaml`.** Quote-style changes on lines the requirement doesn't touch (`"8080"`, `"3000"`, `PORT`, the `api` and `caldav` URLs, `CALFLEX_SMTP_URL`) come from running Prettier on a file that fails it on `main`. Restore the original quoting for every line you did not otherwise change.
8. **Dockerfile.** `FROM dunglas/frankenphp:…` is unqualified while the composer stage is `docker.io/library/…`; qualify it (`docker.io/dunglas/frankenphp:…`). Delete `COPY … record.json /app/schema-record.json` from the `test` stage: no test reads it (the record test runs on the host).
9. **Docs.** `CONTRIBUTING.md` (in your paths): `make verify` now needs `podman compose` for `make test-caldav` through `verify-invariants`, and says what that target does. In `server/caldav/README.md` replace "runtime and RSS budget have not yet been measured" with the figures above (warm `make test-caldav` 21 s, RSS 43 MB of 256 MiB).

Accepted as built: the retained net-bind capability (listed in the PR text); the fixed subnet `172.30.91.0/24` (documented; check-stack ties it to the bind); `CALFLEX_DELEGATION_KEYS` and `CALFLEX_CALDAV_ORIGIN=http://caldav-internal:8081` on `api` (consistent with § Layout, used by E05-R02); the test fixture's 111-line `Europe-Berlin.ics`.

Change nothing else.
