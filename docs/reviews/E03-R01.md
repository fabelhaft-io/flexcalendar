**Security choices for the human approval** (also in the PR; each was exercised, not read):

1. **Public listener**: its own document root and entry, which loads no delegation code and no database and never reads the header; 401 for everything but `GET /healthz`; byte-identical with no header, a valid one, garbage. Outer Caddy also drops `X-Calflex-Principal` on every route.
2. **Internal listener**: its own root, bound to `172.30.91.2` on the `delegation` network (`internal: true`, dynamic pool `172.30.91.128/25`), no published port and no Caddy route; `ECONNREFUSED` from the `stack` network. Only `api`, `caldav` and the one-off test service join.
3. **Delegation check**: strict grammar (six fields, `v=1`, UUIDv4 `p`, canonical base64url), HMAC-SHA256 over method, the request-target as sent, `p`, `t`, `n`; `hash_equals`; keys at least 32 bytes with unique ids, any invalid entry fails closed; ±60 s; the nonce (120 s TTL, pruned in the same transaction) and the `users` row are checked only after the signature, and an unauthenticated request never reaches the database. A nonce is consumed even if the DAV operation fails.
4. **Responses and logs**: one 401 (`Unauthorized`, `no-store`) for every failure; the log gets a fixed reason code and nothing else; DAV errors are SabreDAV's own `DAV:error` elements and headers, never the message, class or trace; no `Server`, `X-Powered-By` or `X-Sabre-Version`.
5. **Principals and ownership**: the principal backend is read-only and returns the acting user only; `allowUnauthenticatedAccess` off, `hideNodesFromListings` on; another user's principal, home, calendar and objects answer exactly as an id that exists nowhere. Until E03-R08, ownership is SabreDAV's `principaluri`, and `MKCALENDAR` does not consult `public.calendars`.
6. **Plugins**: CalDAV, ACL, Sync, PropertyStorage and the delegation identity; no Browser, Locks, Sharing, Scheduling, ICS export or CardDAV.
7. **Container**: uid 10001, FrankenPHP classic mode (asserted by `check-stack` and a unit test), four threads, 256 MiB. The binary keeps its `cap_net_bind_service` (`CapEff 0x400`) although both ports are above 1024; no capability is added.
8. **Keys and INV-07**: the Compose default key is public and development-only; production injects `CALFLEX_DELEGATION_KEYS` from the secret store (D-19). Eight PHP platform entries are added to `invariant-dependencies.json` with their reasons (`ext-ctype`, `ext-curl`, `ext-date`, `ext-pcre`, `ext-simplexml`, `ext-spl`, `ext-xmlreader`, `lib-libxml`). The base image compiles in `sodium`, which the gate cannot see; the code uses only `hash_hmac`, `hash_equals` and `random_bytes`.

Accepted as built, noted in the PR: the retained capability; the fixed dev subnet `172.30.91.0/24`; `CALFLEX_DELEGATION_KEYS` and `CALFLEX_CALDAV_ORIGIN=http://caldav-internal:8081` on `api` (E05-R02 uses them); the `ip_range` check comparing a literal; `dav_failure` logged for every DAV error (follow-up for E08); the test fixture `Europe-Berlin.ics` from tzurl.org.

Follow-ups for other requirements are in `follow-ups.md` (E03-R09, E05-R02, E03-R08, E08).
