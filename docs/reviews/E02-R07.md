## What the reviewer found before run 1 (checked 2026-10-06)

- **`openapi-typescript` 7.13.0 (the latest 7.x) cannot run on the repo's TypeScript.** Its peer is `typescript ^5.x`; the root pins 7.0.2, whose package no longer exposes the compiler API. `npm i` fails with ERESOLVE, and with `--legacy-peer-deps` the CLI crashes on `ts.factory` ("Cannot read properties of undefined (reading 'createKeywordTypeNode')"). With `typescript` 5.9.3 it generates fine. So `packages/api-client-ts` needs its own exact `typescript` 5.9.3 for generation, and pnpm must link the generator's peer to that copy, never the root's 7.0.2. Say why in a comment or the README. The generated types must still typecheck under the repo's TypeScript 7.
- **`swagger_parser` 1.45.0 (pub.dev latest, SDK `^3.6.0`) generates Retrofit clients and `json_serializable` classes.** The `*.g.dart` files come from `build_runner` (`retrofit_generator`, `json_serializable`). It is still pure Dart on `dio`, with no JVM, but the Dart side of `make gen` is two steps. Its README lists starting versions for `dio`, `retrofit`, `json_annotation`, `build_runner`, `retrofit_generator` and `json_serializable`. Take current ones from pub.dev and prove they resolve under Flutter 3.47.6 / Dart 3.13.5.
- `openapi-fetch` is 0.17.0 (no peer dependencies).
- **`spec/openapi.yaml` has `paths: {}`.** A pipeline over an empty contract can never detect a stale client, which makes the gate vacuous. It needs one real operation, and the skeleton in `server/api/src/server.mjs` already has one.
- The implementer sandbox has no Podman, no Dart and no Flutter (`agent-team/README.md` § The sandbox).

   - Add `info.license: {name: Apache-2.0, identifier: Apache-2.0}`; the repo is Apache-2.0 (`LICENSE`).
