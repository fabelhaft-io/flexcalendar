### Independent checks

- **A third oracle for the goldens.** The goldens are "the RFC's answer", and both engines could share a mistake, so I expanded all 34 fixtures with `python-dateutil` 2.9.0 (`rruleset`, `RDATE`/`EXDATE`, overrides by `RECURRENCE-ID`, the same window) in a scratch script: **34 of 34 equal the goldens**, the four ruled fixtures included. The script is not vacuous: moving one instant of `monthly-last-friday-count-6` makes it print `DIFF` and exit 1.
- **The four rulings, each reproduced outside the implementer's runners** (`Reader::read` + `expand` and `EventIterator` for `sabre/vobject`, `ICAL.Event#iterator` with the document's own `VTIMEZONE` for `ical.js`):
  - `minutely-interval-90-count-4`: `vobject` gives `09:00` four times (`expand` and the iterator alike); `ical.js` gives 09:00, 10:30, 12:00, 13:30 = the golden and RFC 5545 § 3.8.5.3's "every hour and a half".
  - `weekly-with-rdate`: `vobject` gives `DTSTART` and the `RDATE` only, two instances; `ical.js` gives the three `RRULE` Tuesdays and the `RDATE` (§ 3.8.5.2: the union).
  - `yearly-byweekno-20-monday-count-5`: `ical.js` gives 2026-05-18, 05-25, 06-01 … (the 20th Monday of the year, then weekly); `vobject` and `dateutil` give 2026-05-11, 2027-05-17 … = ISO week 20. The note's mechanism ("treats the `BYWEEKNO` value as the weekday ordinal and then continues weekly") fits the output.
  - `yearly-leap-day-all-day`: `ical.js` gives 20240229, **20250301**, **20260301** (rolls the invalid date forward and counts it); `vobject` skips non-leap years, as § 3.8.5.3's closing note requires.
- **The gate bites**, live, each reverted with `git checkout`:
  - a ruling removed: `weekly-with-rdate: the engines first differ at occurrences 1 (icaljs …, vobject …), and RULINGS.md has no ruling for it`, exit 1;
  - a ruling for `daily-count-10`, where the engines agree: `… still records a disagreement, but the engines agree now (stale ruling)`, exit 1;
  - one instant of a golden moved: both component suites fail, the PHP one with `daily-count-10: occurrences 2: vobject gives 20260107T090000Z, golden says 20260107T091000Z, and RULINGS.md has no ruling for it`;
  - an engine that cannot run or returns nothing: the first run above.
- **Window mutations.** Window end one **year** short (`2030-01-01`) and window start one day late both fail (2 PHPUnit failures each, and `make verify-corpus` exit 1). Window end one **day** short (`2030-12-31`, both runners) **passes everything** (W1). See follow-up 1.
- `ical.js` runner: it registers each document's `VTIMEZONE` in `ICAL.TimezoneService` for the length of one expansion and removes it in a `finally`; it fails a fixture whose `TZID` the document does not define. That is test code only; `server/api/src` is untouched, so the rule that the API must not register a client's zone globally is not affected.

### Findings that do not block (follow-ups)

1. **The window is not pinned.** No fixture has a `VEVENT` `RRULE` without `COUNT` or `UNTIL` (checked with a script: 0 unbounded of 34), the latest golden instant is 2030-11-05, and nothing sits exactly on `2026-01-01T00:00:00Z` or `2031-01-01T00:00:00Z`. An engine's clipping of an unbounded rule at the window end is therefore never compared, and a window one day short passes (W1). The cases the window exists for ("weekly forever") are the ones missing. Add, to the corpus: an unbounded `FREQ=WEEKLY`, an unbounded `FREQ=MONTHLY;BYMONTHDAY=-1`, an all-day unbounded daily or monthly rule, one instant on the first and one on the last day of the window, and a `DTSTART` before 2026 (the leap-day case already has one). E05-R05 (windowed expansion) and E15-R02 are the natural owners; a second run of E15-R03 would also do.
2. `RecurrenceCorpusTest::testCorpusHolds25To40Fixtures` caps the corpus at 40; the brief's "25 to 40 cases" was a size hint, and this makes the 41st fixture fail the suite. Keep the lower bound (a corpus that shrinks is the danger), drop the upper one.
3. `testWritesNormalisedOutputWhenRequested` is skipped in `composer test` (`CALFLEX_CORPUS_OUT` unset), so the unit suite reports "OK, but some tests were skipped". Writing into a temporary directory instead would run it every time.
4. Product consequences of the rulings, for E05-R04, E05-R05, E05-R07 and the Shared-mode work (details in `docs/reviews/follow-ups/from-E15-R03.md`): `sabre/vobject` 4.6.1 under-reports sub-hourly and `RDATE`-beside-`RRULE` rules, so a stock app's time-range query and the stored first and last occurrence are wrong for them; `ical.js` 2.2.1 expands `FREQ=YEARLY;BYWEEKNO` and a yearly 29-February anchor wrongly, which is the **API's** recurrence authority. Two RFC § 3.8.5.3 examples (`BYDAY=20MO`, `BYWEEKNO=20` without `BYDAY`) were tried and dropped, because one engine rejects the rule and the other cannot produce it (`spec/ical-fixtures/rrule/README.md` says which). Neither upstream is patched here and neither is forked.
