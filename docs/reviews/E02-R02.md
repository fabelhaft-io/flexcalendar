# Review — E02-R02 · Toolchain pinning

- **Verdict: BLOCKED** (review 1, 2026-10-04), reviewed commit `900d4e8` (implementer run 1).
- Branch: `feat/E02-R02-toolchain-pinning`; implementer model `deepseek/deepseek-flash`

Most of the branch works: the Node, pnpm, Dart, Flutter and PHP pins are real, binding, and verified upstream. The block is the Android part. The Gradle, AGP and Kotlin versions are newer than what the pinned Flutter release supports, and the root Gradle build scripts take over files that E10-R01's Flutter scaffold owns. There are also four smaller fixes.

### Fix requests

1. **Pin the Android Gradle wrapper to Gradle 9.3.1**, the version Flutter 3.47.6 supports and uses in its template. Use the official distribution and wrapper files:
   - `distributionUrl=…/gradle-9.3.1-bin.zip`;
   - `distributionSha256Sum=b266d5ff6b90eada6dc3b20cb090e3731302e553a27c5d3e4df1f0d76beaff06`;
   - the 9.3.1 `gradle-wrapper.jar` (published sha256 `b3a875ddc1f044746e1b1a55f645584505f4a10438c1afea9f15e92a7c42ec13`), with `gradlew`/`gradlew.bat` from the same release.

   Regenerate them with `./gradlew wrapper --gradle-version 9.3.1 --gradle-distribution-sha256-sum …` and then check the jar against the published checksum.
2. **Delete `apps/mobile/android/settings.gradle.kts` and `apps/mobile/android/build.gradle.kts`, and pin JDK 21 with Gradle's daemon JVM criteria instead:** `apps/mobile/android/gradle/gradle-daemon-jvm.properties` with `toolchainVersion=21`. Run `./gradlew --version` and report its "Daemon JVM" line. The AGP and Kotlin Gradle plugin versions are not pinned in R02. E10-R01's `flutter create` sets them from the Flutter release that `.fvmrc` pins. Update `apps/mobile/android/README.md`, the `gradle-wrapper.properties` comment and `apps/mobile/README.md` to say where the Gradle and JDK pins live, and drop every mention of AGP/Kotlin pins and the foojay resolver.
3. **`server/caldav/composer.json`: add `"license": "Apache-2.0"`**, so `composer validate --strict` exits 0 (the repo's `LICENSE` is Apache-2.0).
4. **Use the project's name, not "FlexCalendar".** The docs call the project calendar-flex (repo, CLAUDE.md) and "calflex" in protocol names; "FlexCalendar" isn't used anywhere. Rename:
   - root `package.json` `name` to `calendar-flex`;
   - `server/api/package.json` to `@calendar-flex/api`, and the README line that names it in `--filter`;
   - Composer to `calendar-flex/caldav`;
   - the Dart packages to `calendar_flex` (app) and keep `crypto_dart`.

   Replace "FlexCalendar" in every `description` and comment with "calendar-flex". Regenerate `pnpm-lock.yaml` and check that `--frozen-lockfile` still passes.
5. **`pnpm-workspace.yaml`: fix the comment.** It says "Only directories that exist as a package today are listed by path", but it lists `apps/web` by path, which is README-only. Make the comment match the list.
6. **Root `.gitignore`: ignore what these toolchains generate.** Add `.dart_tool/`, `.fvm/`, `apps/mobile/build/`, `apps/mobile/android/.gradle/`, `apps/mobile/android/local.properties` and `server/caldav/vendor/`. Keep `apps/mobile/pubspec.lock` tracked, and ignore `packages/*/pubspec.lock`, because Dart libraries don't commit their lock file. Then run every tool above in the worktree and confirm `git status --short` is empty. `.gitignore` is in this run's writable paths.

Change nothing else. Re-run the checks you can run in the sandbox (`corepack pnpm install --frozen-lockfile`, `./gradlew --version`, JSON/YAML parse) and list the rest for the reviewer.
