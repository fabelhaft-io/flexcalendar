## Findings

- **INV-05 is broader than the invariant.** INV-05 in `06` forbids clients to *emit* `EXDATE`/`RECURRENCE-ID`. The check rejects every case-insensitive `exdate`, `recurrence_id`, `recurrenceId` and `recurrence-id`, in comments too. The sidecar key, the E12 envelope binding (`recurrence_id` encodings pinned in E04-R04) and E10-R03's cache all need the `recurrence_id` identifier in client code (controls 3, 4).
- **INV-07 is default-deny over all server dependencies.** E02-R05 says "no libsodium, tweetnacl, `@noble/*` or similar content-crypto package (allow-list with justification for TLS/hash libs)". The allow-list is for crypto-looking libraries that are legitimate. Instead, `invariant-dependencies.json` lists all 124 current dependencies (46 npm, 62 Composer, 16 platform), and the npm entries all share one boilerplate sentence. Every dependency bump that adds a transitive breaks `make verify` (control 7), and the copied justification proves nothing.
- **Diagnostics name nothing.** File paths and package names are not event content. A developer gets "unreviewed server dependency" without the dependency, and "forbidden … reference" without the file.
- **Symlinks abort the scan** (control 5). Flutter writes symlinks under `ios/.symlinks` and `**/ephemeral/` on every `pub get`.
- The tests create their trees under `infra/scripts/.invariant-test-*`. A crashed test leaves an untracked directory in the repo.

Scope: all eight files are inside `--paths`; no lockfile change, no secrets, no event content, no new dependency.

## Fix requests

1. **INV-05 targets emission.** Match the iCalendar property *names*, case-insensitive: `EXDATE` and `RECURRENCE-ID` (with the hyphen) as a whole token. Don't match the identifiers `recurrence_id` and `recurrenceId`. Add good fixtures for both identifiers (controls 3 and 4 must pass) and keep the bad fixtures for the property names.
2. **INV-07 is a deny check with a narrow allow-list:**
   - keep the explicit deny pattern, which always fails;
   - add a crypto-name heuristic: names containing `crypt`, `cipher`, `sodium`, `nacl`, `aes`, `chacha`, `salsa`, `poly1305`, `25519`, `secp`, `elliptic`, `jose`, `jwe`, `pgp`, `openssl`, `tls`, `ssl`, `hash`, `hmac`, `sha`, `argon`, `bcrypt`, `scrypt` or `pbkdf`. The short ones (`aes`, `sha`, `tls`, `ssl`, `jwe`, `pgp`, `jose`) match only as a whole name segment, delimited by the start or end of the name, `-`, `_`, `.`, `/`, `@` or a digit, so that `sha256` matches and `shared-utils` doesn't. A dependency matching the heuristic fails unless it is in `invariant-dependencies.json`;
   - every other dependency passes;
   - reduce the allow-list to the entries the heuristic hits in the current trees, each with its own specific reason. PHP platform requirements keep their explicit list.
   - Add a good fixture for a harmless new dependency (control 7 must pass), and a bad one for a heuristic hit that isn't allow-listed.
3. **Diagnostics name the culprit**: INV-05 prints the repo-relative file path; INV-07 prints the package name and version; an input error names the file it could not read or parse. Never print source lines or file contents. Update the tests' expected messages.
4. **Don't follow symlinks** in the scan. Skip them, and skip the directories `.symlinks` and `ephemeral`. Add a fixture with a symlink that passes.
5. Create test trees with `mkdtempSync(join(os.tmpdir(), …))`, not inside the repo.
6. Update `infra/scripts/verify/invariants/README.md` to match.

Change nothing else.
